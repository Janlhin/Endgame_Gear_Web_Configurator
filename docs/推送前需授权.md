# 推送前需要你做的一件事：给Git 令牌加 workflow 权限

## 为什么需要

推送被 GitHub 拒绝了，原话是：

```text
! [remote rejected] main -> main (refusing to allow an OAuth App to create
  or update workflow `.github/workflows/deploy.yml` without `workflow` scope)
```

意思是：**当前令牌的权限不够**，无法上传 `.github/workflows/` 里的文件。
本项目的 `verify.yml`（CI 校验）与 `deploy.yml`（Pages 发布）都在这个目录里，
所以 GitHub 直接拒绝了整个推送。

这不是代码问题，也不是网络问题。远端仓库存在且可访问，只是令牌少一个权限。

### 路线 A：重新授权已有的 OAuth App（推荐，`gh` 已确认可用）

`gh` 实际路径：**`C:\Program Files\GitHub CLI\gh.exe`**（v2.102.0，winget 安装）。
注意它**不在 Git Bash 的 PATH 里**，用 PowerShell 调用时建议直接写完整路径：

```powershell
& "C:\Program Files\GitHub CLI\gh.exe" auth refresh -s workflow
```

1. 执行上面的命令，会打印一次性设备码并让你回车打开浏览器
2. 浏览器打开 <https://github.com/login/device>，粘贴该码并授权
3. 回到项目验证 scope 是否已加上：

```powershell
& "C:\Program Files\GitHub CLI\gh.exe" api -X GET user -i 2>&1 |
  Select-String "X-Oauth-Scopes"
# 应出现：gist, read:org, repo, workflow
```

scope 确认含 `workflow` 后，回来我重试推送。

若 `gh auth refresh` 因令牌由其他工具托管而报错，改走路线 B。

### 路线 B：新建一个带 workflow 权限的令牌

1. 打开 <https://github.com/settings/tokens/new>
2. **Note** 填个名字，比如 `endgame-gear-push`
3. **Expiration** 选个期限（推完就可以不用了，建议 30 天）
4. 勾选仓库权限里的 **`workflow`**
5. Generate，复制那个 `ghp_...` 开头的串（**只显示一次**）
6. 回到项目目录执行：

```bash
cd "C:/Users/Janlhin/WorkBuddy/2026-10-08-19-20-54/endgame-gear-web-configurator"
git remote set-url origin https://<你的用户名>:<那个令牌>@github.com/Janlhin/Endgame_Gear_Web_Configurator.git
git push -u origin main
```

>提醒：把令牌写进 remote URL 会让它留在 `.git/config` 里。
> 推完之后执行 `git remote set-url origin https://github.com/Janlhin/Endgame_Gear_Web_Configurator.git`
> 把带令牌的 URL 换回干净的地址，wincred 凭据助手会接管后续认证。

## 推完之后会发生什么

`deploy.yml` 对 `push: main` 会**自动触发 Pages 发布**——也就是这一步等于上线。
你之前已知悉并接受，这里再确认一次，避免意外。

推成功后会启动两个 CI job：

| job | 跑在哪| 做什么 |
|---|---|---|
| `verify` | ubuntu | `npm ci` → `verify:ci`（含 tsc、markdownlint、217 项断言、i18n 审计、构建）+ 产物绝对路径检查 + 提交信息格式检查 |
| `ui` | windows-latest | 无头 Edge 的 8 类布局 + 22 个语言检测用例 + 复位演练 |

**这是 CI 的首次真实运行**，本地全绿不能替代它的结论。两处此前未能验证的差异会在此暴露：

- 本地 `check:ui` 跑 Python 3.13.14，CI 声明 3.12
- runner 上的无头 Edge 会被自动更新，与本地版本不一定一致

我会去看这两个 job 的结果并汇报。

## 我被否决的替代方案

有人会想「把 workflow 文件排除掉，先把代码推上去」——我试这条路是错的：

- CI 与 Pages 部署会**完全失效**，且失效状态不会立刻暴露
- 本地工作树要临时缺两个文件，等于制造一个不一致的状态
- 用更大的问题换小问题，不划算

所以正确路径就是补权限。
