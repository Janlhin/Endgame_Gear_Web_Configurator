# 远程志愿者测试流程（未验证型号）

> 给手里有**我们没有的鼠标**（8k 有线全系、XM2we / OP1we）的人。
> 你的每一次实测都是这个项目往前走一步的唯一途径 —— 但前提是**别把鼠标写坏**。
>
> 本工具对这些型号**默认只读**。要写入，你得点一次确认；确认后只在你这次连接里有效，
> 刷新页面或拔掉设备就自动回到只读。
>
> **具体要测哪些项 → 看 [`docs/test-checklist.md`](test-checklist.md)**（本文只讲流程与风险）。
>
> **照着 [`docs/test-checklist.md`](test-checklist.md) 逐条打勾就行** —— 每条都写了怎么测、
> 什么算通过、不通过说明什么。这份清单和下面的流程是配套的。

---

## 一、开始前（必做，两分钟）

1. **用官方工具把当前配置截图存好**，或者记下：CPI 四档各是多少、回报率、LOD。
2. **知道怎么恢复**：官方工具里都有"恢复出厂"。真写坏了用它救回来。
3. 用 **Chrome 或 Edge** 打开本工具（`index.html`），不要用 Firefox / Safari（没有 WebHID）。

## 二、第一次写入（会弹确认）

1. 连接你的鼠标 → 等它读出配置。
2. 页面会提示"这一型号没有经过真机验证"。这是正常的，不是你的设备有问题。
3. **只改一个值**（建议先改 CPI 第 1 档，比如 800 → 1600），点"应用"。
4. 弹出确认框，里面会说明风险。**点确定之前，页面会自动导出一份当前配置备份 —— 请先把它保存好。**
5. 写入后页面会**回读一次并显示校验结果**：
   - 显示"已回读校验通过" → 记下这一条；
   - 显示"回读不一致"并列出哪一项 → **不要重试**，把日志发我。

## 三、把结果发回来（一步搞定）

点 **「导出测试数据包 (.json)」**（工具卡片里；XM2we / OP1we 在它自己的卡片里）。
这一个文件里已经有：

- 型号名、**VID / PID**、**接口集合（usage page）** —— 判族的第一手依据
- 固件版本（鼠标 / 接收器）、电量、有线还是无线
- 解析出来的全部设置（CPI 四档、回报率、LOD、角度、过滤……）
- **完整的 1024B 配置 blob**（base64 + hex 对照）／WE 族则是 EEPROM 转储与解码表
- 本次会话的**通讯日志全文**

包里还带了一份 `report` 回报模板，请你填这四项：

| 字段 | 填什么 |
|---|---|
| `modelSeen` | 页面上显示的型号（不用改，照抄即可） |
| `changed` | 例："CPI 1：800 → 1600" |
| `readBack` | 页面提示"已回读校验通过"，还是列出了不一致项 |
| `feltDifferent` | ★ **实际手感 / 速度真的变了吗** |

> 最关键的一条：**改完之后手感/实际速度真的变了吗？**
> 回读校验只能证明"鼠标按我发的数字存了"，证明不了"这个数字就是你想要的意思"。
> 比如 CPI 设 1600 却明显快了一倍，说明我们的编码理解错了 —— 这种反馈比什么都值钱。

## 四、如果出问题

| 现象 | 怎么办 |
|---|---|
| 写入后鼠标变得不能用 / 速度离谱 | 用官方工具"恢复出厂"，或导入第 4 步自动导出的备份 |
| 页面报"回读不一致" | **停止重试**，把日志发我 |
| 连不上 / 读不出来 | 换一个 USB 口、拔插一次；无线鼠标先动一下唤醒它 |
| 页面卡住、鼠标指针不动了 | 直接关掉标签页即可恢复（工具不会开鼠标指针接口） |

## 五、已知不适用的操作

- **导入配置**：8k 全系禁用（整块覆盖，风险过高）；其余型号只能导入**同一代**的配置。
- **配对命令**：对有线 8k 没有意义，界面已禁用。
- **恢复出厂**：可用，但需要两道确认，且**不可撤销**。
