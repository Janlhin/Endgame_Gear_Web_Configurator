## 4. 风险

1. **远端为空，CI 从未运行**（T-09/T-11）。`verify.yml` 与 `deploy.yml` 配置完整但**从未在GitHub Actions 上执行过一次**。本地 verify 全绿不等于 CI 绿——`check:ui` 依赖 Windows 预装 `msedge.exe`，在 ubuntu runner 上跑不了，拆分逻辑是否正确**未经真实 runner 验证**。
   - 已核实：Edge 确实预装于 `windows-latest` runner，路径 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` 与 `re/layout_check.py:7` 硬编码的 `EDGE` 一致；`re/*.py` 仅用标准库（`os`/`re`/`subprocess`/`sys`/`tempfile`/`io`），无需 `pip install`，故 `verify.yml` 缺 pip 步骤不构成缺陷。
   - 未核实：Python 版本差异。本地实测于 **3.13.14**，CI 声明 **3.12**。已确认 py 脚本未使用 3.13 独有语法，但仍存在未覆盖的版本差异面。
   - **未核实且无法本地验证**：`msedge.exe` 在 runner 上被自动更新后，无头模式的行为是否与本地一致。
2. **写入路径是安全关键路径**。项目历史上发生过真实事故：XM1 早期版本误把官方写路径当读路径，向设备发了 1024 字节全零负载，**导致用户 DPI/CPI 被清零**（`README.md` 有完整事故记录）。当前防护为「23 个已实测确认偏移的白名单 + 其余1001 字节必须与读回值逐字节相同 + 写入后回读校验」，并由 `re/test_write_gates.ts` 覆盖。**任何触及 `sendFeatureReport` 的改动都可能重演该事故**。
3. **esbuild dev server 漏洞**（T-17）。判定不影响交付物，但 `npm run dev`（`build.mjs --watch`）期间本地会暴露开发服务器。
4. **82 处 `any` 集中在协议边界**（T-13）。`connect.ts`、`device-8k.ts`、`device-xm1.ts` 的 HID 数据处理正是主规范要求运行期 schema 的位置，当前靠手写校验与写入白名单兜底。
5. **无覆盖率计量**（T-15）。测试全绿属实，但无法回答「这次改动是否降低了覆盖」——CI 的绿灯在覆盖率维度上是盲的。
6. **真机验证是硬约束瓶颈**。17 款目标中仅 6 款真机验证过；剩余 11 款依赖物理硬件，**AI 无法通过任何命令消除这一差距**。
7. **项目仅存续1 天**（2026-10-08 → 10-09，84 次提交）。迭代密度极高，缺少跨时间的稳定性证据。
