# 网页版能做、而官方工具没有（或没做）的功能

> 目的：明确本项目的**差异化价值**与每一项的**前置条件与证据**。
> 原则：**没有证据支撑的功能不写进来**；写入类功能一律以"协议已核实"为前提。
> 关联文档：`README.md`、`re/XM1_NOTES.md`、`re/PROTOCOL_NOTES.md`、
> `docs/official-product-catalog.md`。最后更新 2026-10-09。

## 一、已经实现并可用（官方没有）

### 1. XY 独立 CPI ★

| | 官方 v1.02 / v1.09 工具 | 本网页版 |
|---|---|---|
| CPI 输入 | 每档**一个**输入框（X = Y） | 每档 **XY 开关 + 独立 X / Y 输入框** |
| 协议层 | 固件**本就分开存储** | 直接读写两个独立 u16 |

- **协议依据**：4k 族每档 5 字节 = `[XY启用][X:u16 LE][Y:u16 LE]`
  （`src/main.ts` 的 `0x23 + 5n`）；XM1 实测同为 `[X:u16][Y:u16]` 相邻两份
  （`re/XM1_NOTES.md` 6.7 节，差分确凿）。
- **官方侧证据**：XM1 官方工具的对话框资源里**存在** `Enable XY` 与
  `XY1/2/3 TEXT` 输入框（`re/XM1_NOTES.md` 6.10 节）——控件在，功能没启用。
  即官方是"有控件没做功能"，不是能力不支持。
- **适用范围**：4k 族（含 8k 有线）**已生效**（写入通道已验证）；
  XM1 读取已通、写入停用中（见第二节）。
- **待真机确认**：把某档设为 X ≠ Y（如 X=800 / Y=1600）后回读，
  应能读回两个不同值，且指针横向/纵向灵敏度不同。

### 2. 可读的 JSON 配置导出

导出为**带字段名**的 JSON（`blobB64` + `blobHex` + 设备/时间/代数）。
官方只有自有格式的 Import / Delete / Reset —— 无法用于：
备份到版本库、两台设备对比、把配置贴进 issue / 论坛求助。

### 3. 字段级只读解析视图

把 1024 字节 blob 解成可读表（CPI 四档值与启停、当前激活档、
Lift Cut-Off、Ripple、按键表…），官方只呈现它自己的 UI 形态。

### 4. 零安装 / 免管理员 / 跨平台 / 开源可审计

- 官方：Windows `.exe` 安装器（含驱动组件），需安装、需管理员、仅 Windows
- 本工具：单个 HTML，Chrome / Edge 直接打开；源码公开可审计
- **动机不是空谈**：2025-06/07 官网分发的 OP1w 4k v2 配置工具曾被植入 **XRed 木马**
  ——"第三方可审计"是这类事故的直接对冲手段（见 `docs/email-to-endgamegear.md`）

### 5. 中英双语 + 深色主题

官方仅英文；且 XM1 工具对话框里仍残留 `TITAN X/V/M MOUSE`、`Model Name`
等**共用 OEM 模板**的旧字样（`re/XM1_NOTES.md` 6.10 节）。
样式层已是 SCSS 令牌化，深色主题只需加一组 token 覆盖，组件无需改动。

### 6. 离线 blob 分析

不上机也能把历史导出的固件快照解析成字段表 —— 逆向与排障都用得上
（本项目的差分分析就是这么做的，脚本见 `re/xm1_blob_struct.py`）。

## 三、做不了 / 不建议承诺

| 项 | 原因 |
|---|---|
| **回报率（XM1）** | **鼠标底部 3 档硬件拨动开关**（250/500/1000 Hz），由 GPIO 读取，**软件无法修改**；官方也改不了（`re/XM1_NOTES.md` 6.11 节） |
| **回报率（4k 族）** | 协议里是**枚举写入**，可实现；但**未在真机验证过**，需要受控写入测试 |
| **固件升级** | 官方另有 `Firmware Update Tool`，`.fub` 载荷加密；刷坏会进 bootloader（两 LED 同时红闪）。风险与收益不成比例 |
| **宏编辑** | 宏的存储位置与编码格式未确认（可能在 PC 侧文件），协议未定 |
| **任何未验证的写入路径** | 2026-10-09 已付代价：发送未核实形态的 1041B 报文把用户鼠标的 DPI/CPI 清零。**未核实即不发**是硬红线 |

## 四、产品级增强（官方完全没有，取决于你想要的形态）

| 想法 | 说明 | 依赖 |
|---|---|---|
| **配置快照 diff** | 把逆向时的"差分法"做成 UI：两份快照对比，高亮变化字节 | 无（纯前端） |
| **多设备配置管理** | 一次保存多只鼠标的配置并互相套用 | 无 |
| **配置分享链接** | 生成链接把配置分享给他人（"我的 800/1600 手感配置"） | 需要后端（云服务） |
| **命令行 / 脚本化配置** | 批量化、CI 友好 | 需要 Node 侧 WebHID 方案 |
| **无障碍** | 全键盘可操作、屏幕阅读器标注、高对比度 | 无 |

## 五、优先级建议（按"证据完备度 × 用户价值"）

1. **XY 独立 CPI 在 4k 族真机验证** —— 代码已在，只差一次写入 + 回读确认；
   这是**官方明确没做**的功能，验证成本最低
2. **单字节通道对照实验** —— 拨一下底部开关即可定性，能解锁"读取更多全局状态"
3. **XM1 写入**（重排层）—— 价值最高但成本最高，且是最危险的一步，必须逐字节核实后再谈
4. **8k 系列支持** —— 只差 PID，做完成本几乎为零
